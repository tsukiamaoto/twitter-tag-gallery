# 015 圖片卡片標籤精簡與列表查詢

狀態：done（已套用正式服務）  
完成日期：2026-10-21

## 需求

「最近」翻頁延遲主要包含整頁標籤讀取及縮圖存取。卡片不需顯示大量標籤，先精簡顯示與查詢資料量。

- 卡片最多顯示一位畫師，保留修改時間、建議歸檔及媒體／分級提示。
- 角色、作品與一般標籤在詳情查看；搜尋與篩選仍可使用完整標籤。
- Web 列表使用 compact 模式，只讀畫師與分級的內容；MCP 與既有列表 API 預設保留完整回應。
- 使用現有關聯索引篩選所需標籤，避免讀取一般標籤的 confidence／source；完整標籤數以索引計數。

## 驗收

- [x] 精簡模式保留最高信心畫師、分級及正確標籤總數；信心相同時依 tag_id 固定排序。
- [x] 完整詳情、MCP 搜尋與標籤篩選不受影響。
- [x] 瀏覽器確認卡片最多一個畫師，無角色／作品／一般標籤。
- [x] 量測改版列表資料量與翻頁耗時。

初始量測與腳本：`.tag_gallery/ui-review/recent-page-profile.json`、`.tag_gallery/ui-review/recent-page-profile.cjs`。

## 實作與驗證

- 前端請求 `/api/images?compact=true`；API 預設仍使用完整模式。沒有修改詳情與 MCP 工具介面。
- 精簡 SQL 使用 materialized CTE 與既有 `(image_id,tag_id)` 涵蓋索引，先篩出畫師與分級，再讀其 confidence／source，避免一般標籤的關聯內容讀取。SQLite 需要 3.35+；本機為 3.40.1。
- Python 112 項、Node 29 項通過。六組瀏覽器測試全部通過，包含 15 種畫面寬度、詳情、刪除與多選。

- 套用紀錄：`.tag_gallery/compact_cards_activation_20261021_223251.json`。

## 量測與限制

第 40–45 頁、每頁 100 張，交替執行完整與精簡模式；回傳 JSON 大小中位數由 139,594 bytes 降為 46,750 bytes，減少約 66.5%。總標籤數保持一致。量測不排入縮圖預取。

查詢耗時受先後順序和磁碟快取影響明顯，本次不能從交替量測推論固定加速比例，也沒有清除 OS 快取。暖快取的原查詢仍可能更快。這次主要確定降低不必要的標籤內容讀取、回傳資料量及卡片資訊密度。
