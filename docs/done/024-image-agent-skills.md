# 024 影像修補 Agent Skill 與指定模型

更新日期：2026-10-24

## 行為與儲存

- Skill 管理使用同一份 Agent Skill 清單，影像修補不再是獨立的預設值區塊。
- 影像修補技能的專用表單可編輯名稱、用途、工作流程、修補 Prompt、指定 GGUF 模型、步數與種子。模型檔案的下載及管理仍在 AI 模型頁。
- 所有技能均以 `.agents/skills/<id>/SKILL.md` 為來源。影像技能使用 `metadata.gallery.kind: image-repair`，`metadata.gallery.config` 保存影像執行設定，Markdown 正文保存 Agent 工作流程。
- 影像表單與 Markdown API 編輯相同文件，使用共用鎖、原子替換、版本衝突檢查及文件備份。表單保留額外 frontmatter 與 metadata；舊客戶端未傳入工作流程時保留既有正文。
- 一般 Agent Skill 的模型由外部 AI 客戶端管理；影像修補由本機執行器依技能指定的模型處理。

## 遷移與執行

- 第一次讀取技能清單時，先將舊 `image_skills/skills.json` 備份為同資料夾內的 `skills.before-agent-skills.json`，再逐份匯入 Agent Skill。原 ID、Prompt、指定模型、推論參數、套用選擇及封存紀錄保留。
- 完成文件匯入後才將 JSON 更新為 version 2，保留原技能 ID 索引、套用 ID 及封存紀錄。後續內容由 SKILL.md 讀取，外部安裝的影像技能亦可直接被發現。
- 匯入中斷可重跑，依來源路徑辨識先前已匯入文件，保留中斷後的文件編輯。若同 ID 已存在其他文件，回報衝突並保留原資料。
- 執行修補以 Skill 指定模型為準。AI 模型頁後來的選擇不覆蓋技能；指定模型無法載入、實際載入模型不符，或套用中的技能損壞／缺失時停止並顯示錯誤。
- 封存影像技能會保留完整 SKILL.md 至 `.agents/skills/.storage/archived/`，並更新套用狀態；索引寫入失敗會還原文件。

## 驗證與套用

- 隔離後端測試涵蓋舊資料遷移、可重跑恢復、匯入衝突、雙編輯器一致性、過期版本、模型路徑驗證、建立／套用／封存、工作流程相容性與模型派送。
- 完整 Python 回歸 233 項、JavaScript 單元測試 40 項及 14 組瀏覽器回歸通過；最後的自訂模型系列派送情境另以 9 項影像技能測試確認。介面機械檢查無發現。
- 瀏覽器測試使用同時含一般與影像 Agent Skill 的模擬資料，確認同一清單內不重複顯示，以及指定模型與工作流程可儲存。桌面及手機截圖已檢查；320–1440 px 編輯視窗無水平溢出，儲存按鈕可見。
- 測試僅使用暫存技能、暫存圖庫、模擬 API 與假的 GPU 模型呼叫；未啟動正式圖片修補。
- 重新啟動圖庫後端並重新整理頁面即可套用。外部 AI 客戶端依自身機制重新載入技能。
