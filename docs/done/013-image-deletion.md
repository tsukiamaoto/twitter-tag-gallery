# 圖片單檔、多選刪除與 Del 快捷鍵

日期：2026-10-21

## 行為

- 勾選圖片後，批次工具列提供「刪除選取檔案 (Del)」，包含跨頁選取。
- 單張詳情提供「刪除檔案 (Del)」。在詳情按 Del 只刪除目前這張。
- 圖庫按 Del 刪除已選取項目；沒有選取時，可刪除目前鍵盤焦點所在的圖片卡片。
- 刪除前確認數量、最多五個檔名與跨頁選取數量。取消不送出請求。
- 輸入欄位、影片控制、輸入法組字、其他對話框、組合鍵與長按重複事件不觸發刪除。
- 成功後同步選取、圖片、統計、標籤與資料夾；刪完末頁會調回有效頁碼。
- 「復原剛才刪除」保留最後一次成功刪除的批次，重新整理後仍可復原。
- 刪除提示提供「關閉提示」，記住該批次的關閉狀態，重新整理後不再顯示；管理工具仍可「復原上次刪除」。下一次刪除會顯示新的提示，復原成功後清除復原編號與關閉狀態。

## 檔案與資料

`POST /api/images/delete` 接受明確的正整數 `image_ids`（最多 10,000 個），全批檢查 ID 與檔案後執行。檔案實際移到原圖庫的 `.tag_gallery/trash/<operation_id>/`，同步移除 SQLite 圖片與關聯索引；掃描會略過回收區。這是圖庫自己的回收區，並不釋放磁碟空間。

`POST /api/images/deletions/<operation_id>/restore` 復原原位置、圖片 ID、人工與自動標籤、翻譯及處理階段。原位置有同名檔、索引衝突或回收區內容已修改時，停止全批復原，不覆蓋檔案。失敗後可重試，已復原的批次不可重複執行。

使用既有 `exclusive_job` 與 `file_operations.execute`：完整計畫持久化後才搬檔，資料庫一次提交；搬移或寫入失敗會回滾，程序中斷可由既有復原工具處理。刪除日誌保存必要的圖片、標籤及處理資料，復原交易失敗時也會退回回收區。

介面提供最後一批的復原按鈕；更早批次的 ID 留在操作日誌，可透過復原 API 處理。本次未增加回收區清空或永久刪除功能。

## 系統資源回收筒直連與刪除效能最佳化（2026-10-23）

針對機械硬碟（`D:\圖檔\twitter`）刪除圖片耗時數秒至十餘秒的瓶頸進行改版：

- **改用 Windows 系統資源回收筒**：移除自建 `.tag_gallery/trash/<operation_id>/` 兩階段搬移與檔案交易日誌，改由 `SHFileOperationW`（`FO_DELETE` + `FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_NOERRORUI | FOF_SILENT`）直接將檔案批次移入 Windows 資源回收筒，並將既有 `.tag_gallery/trash` 內 20 個檔案移入系統資源回收筒後清理目錄。
- **單一資料庫交易與索引最佳化**：`delete_images` 於單一 SQLite 交易內完成 `DELETE FROM images`、`refresh_tag_counts` 與資源回收筒移入（任一步驟失敗即自動回滾）；移除重複的 `idx_image_tags_img` 索引、將 `idx_image_tags_tag` 升級為 `(tag_id, image_id)` 覆蓋索引，並新增 `idx_images_folder_mtime(folder, mtime)` 覆蓋索引。
- **快取原位更新**：新增 `remove_deleted_images_from_cache`，在刪除後直接從 `natural_order` 快取過濾已刪除的圖片 ID，避免每次刪除都重新對 3 萬筆路徑執行 `StrCmpLogicalW` 全量排序。
- **無確認視窗、無成功橫幅、立即解鎖連續刪除**：移除刪除前 `window.confirm` 與介面內「復原剛才刪除／復原上次刪除」按鈕；一般刪除成功時不再顯示頂部提示橫幅（僅在刪除失敗或補載異常時顯示）；`/api/images/delete` 完成並切換目標圖片 ID 後立即解除按鈕與 `Del` 快捷鍵鎖定，不再等待背景原圖解碼或側欄重載。
