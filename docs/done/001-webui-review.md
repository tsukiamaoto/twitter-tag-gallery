## 檢查範圍

實際開啟 `http://127.0.0.1:8765/`，檢查主畫面與排程視窗，並對照 `static/index.html`、`app.py`、`scheduler.py`。

## 結論

主要問題是資訊層級與操作入口不一致。瀏覽、批次管理、系統設定都放在頂部；多個彩色主按鈕同時爭取注意力。排程視窗同時展開長篇說明、時間、來源、處理細節及紀錄，增加掃讀成本。

| 問題 | 現有證據 | 改善方向 |
| --- | --- | --- |
| 排程說明過密 | 長標題、多色框、重複路徑、六個處理選項全部展開 | 移至設定，基本設定優先，處理細節與說明按需展開，紀錄獨立 |
| 取消篩選難找 | 中央已有 chip，但使用可點擊的 div 與小叉號；左欄排除狀態不明顯 | 固定已選條件列，真正的移除按鈕，包含／排除狀態一致 |
| 每頁數量不可改 | 前端固定 `pageSize: 60`；API 已支援 10–200 | 每頁數量控制及瀏覽偏好保存 |
| 方向鍵只支援詳情 | `keydown` 只在 detail modal 開啟時生效 | 圖庫左右翻頁；輸入、設定、其他彈窗不觸發 |
| 缺少停留預覽 | 縮圖只向上位移，點擊才開詳情 | 延遲顯示完整比例預覽，不推動版面 |
| 窄畫面工具列溢出 | 實際窄視窗中搜尋框幾乎被壓扁，排序超出畫面，分頁文字過度換行 | 搜尋列、設定與分頁區響應式換行 |
