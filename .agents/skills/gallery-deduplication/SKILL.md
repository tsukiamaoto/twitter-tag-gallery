# 圖庫去重

使用目前已連線圖庫的 `gallery_clean_duplicates`，以工具回傳的圖片 ID、路徑與設定為準。
預設圖庫為 `D:\圖檔\twitter`，可由 `TWITTER_GALLERY_ROOT` 調整，不把預設路徑當作實際操作範圍。

## 選擇比對模式

- `exact`：資料庫 SHA-256 分組後，再以實體檔案逐位元組驗證。適用靜態圖、動畫及影片的完全相同副本。
- `visual`：靜態圖的 dHash/pHash 初篩，再以縮至 512×512 的 RGB 計算全域 SSIM、MAE 與顯著差異比例。
  排除多幀 GIF、WebP、APNG 等動畫，避免只因首幀相同而刪除不同動畫。
- `both`：同時執行前兩種比對，預設使用此模式。

視覺比對是相似度啟發式，不能保證辨識所有表情、文字、浮水印或服裝差分。
預設 `MAE <= 6.5`、`SSIM >= 0.95`；任一通道差異超過 45/255 的像素比例須 `<= 0.005`（0.5%）。
低對比或面積更小的差分仍可能通過，縮小圖片也可能掩蓋差異。不要把通過門檻當作完全相同的證明。
參數界限與可調值以工具 schema 為準。

同群組依總像素數、PNG 格式、檔案大小、已歸檔資料夾、乾淨檔名、較小圖片 ID 的順序選擇保留圖。
這是固定排序，不能保證原始版本或最高藝術品質。

## 預覽與清理

1. 先用 `execute_delete=false` 預覽。`scope=same_folder` 僅比對同資料夾，`scope=all` 跨資料夾；
   `folder=__ALL__` 選全庫、`__ROOT__` 選根目錄，亦可指定資料夾名稱。
2. 啟動回應提供 `run_id`。用 `gallery_get_tool_run(run_id)` 查到 `run.status` 不再是 `running`，
   再讀 `run.result` 的群組、保留圖、副本及可釋放空間。檢視視覺候選的細微差分。
   `max_groups` 只限制回傳群組數，不限制刪除範圍；`groups_truncated=true` 時不要假設已看完全部候選。
3. 確定使用者已授權所選範圍的刪除後，沿用同一範圍與門檻傳 `execute_delete=true`。
   此呼叫會重新掃描，沒有綁定前次預覽快照；圖片有變動時先重新預覽。
   MCP 執行會清理全部匹配群組；需要勾選個別副本則使用 Web UI。
4. 後端先建立 SQLite 備份，合併副本的核心分類與人工標籤，再將多餘副本移至系統資源回收筒。
   資料庫備份不包含原圖，還原圖片須透過資源回收筒處理。

停止時照啟動回應的 `cancel_tool` 與 `cancel_arguments` 呼叫；本工具使用非空的共用圖庫作業 `job_id`，
不能拿 `run_id` 代替。保持 MCP 連線至工具結束，回報實際清除數、失敗項目與備份檔。
